## 0.1.0

### 新增内容

- 施工终端材料库可按物品显示名或物品 id 搜索，只显示匹配的非空格；清空搜索恢复原 100 页，真实库槽位不重排；搜索框聚焦时 Esc 仍可关闭界面（E 键不会误关）
  - Construction terminal vault can search by item name or id and shows only matching occupied slots; clearing the query restores the original 100 pages without rearranging real vault slots; Esc still closes the GUI while the search box is focused (E does not)
- 领单时「工位是否空闲」改用小范围实心落脚探测，不再对每个候选格做整圈曼哈顿+视线搜工位，避免多女仆一进存档就把服务端拖到数秒一拍
  - Claim-time free-stand checks use a small solid-footing probe instead of a full Manhattan+LOS stand gather per candidate, so many maids no longer stall the server for seconds on world join
- 目标周围完全没有结实工位时（脚手架也会 `noSolidStand` 规划失败），领单后立刻从材料库隔空放置，不再 IDLE 空转约 3 秒再松手换格；**有工位时卡住先传送到工位**，不再抢先隔空
  - When a target has no solid work stand at all (scaffold planning also fails with noSolidStand), maids vault-place from the material stock on claim instead of idling ~3s then abandoning; **with a work stand, stuck recovery teleports to the stand first** instead of vault-placing ahead of teleport
- 取消施工重寻路 / 脚手架全量重规划的额度限制（不再每女仆约 1 秒一次、也不再全工地每拍最多一次）；同格寻路失败满 1 次且卡住约 3 秒即可库隔空；攀爬放架 blocked 第 1 次就传送到工位
  - Construction heavy pathfinding / full scaffold replan no longer has per-maid or per-tick quotas; vault-place after one path-failure sample plus ~3s stall; climbing scaffold place-blocked teleports to the work stand on the first attempt
- 目标周围没有结实工位时，找工位不做可达性试探，直接走脚手架或隔空，避免对着空气白跑寻路
  - When a target has no solid stand, stand search skips path probes and goes to scaffolding or vault-place instead of wasted pathfinding
- 传到已经算好的工位时，不再因为垂直高度差超过 6 格而取消。找不到落脚点时，仍不会把人扔到建筑半空的高度图上；同一根柱子直线上抬超过 8 格仍拒绝，避免竖井里抬上去再摔下来
  - Teleport onto an already chosen work stand is no longer cancelled for a vertical gap over 6 blocks. With no stand, maids are still not thrown onto the building heightmap; a straight same-column lift over 8 blocks is still refused so a shaft teleport cannot drop them
- 某个目标周围没有结实工位时，大约每秒才再扫一次附近空气，不再每个游戏拍把目标旁边一千多个格子重读一遍
  - After a target has no solid stand, the air around it is rescanned about once a second instead of rereading over a thousand neighbouring cells every tick
- 施工工位只认脚下结实的落脚点：悬空空气格即使几何上够得着、看得见也不再当工位；附近没有实地工位时走脚手架或隔空，不再对着天上假工位罚站
  - Construction work stands require solid footing: floating air cells are no longer stands even when reach and line-of-sight pass; with no solid stand nearby maids scaffold or vault-place instead of staring at a fake mid-air stand
- 工程真正结束后（自动完工或终端强制完工），参与施工的女仆工作模式自动切回「空闲」，不再停在「施工」
  - When a job truly ends (auto-complete or Hub force-finish), participating maids' work mode switches back to Idle instead of staying on Construction
- 待建格四面与上方都是空气或可替换时（不查正下方），女仆领到后立刻从材料库隔空放置，不再寻路搭架
  - When the four sides and above of a pending cell are air or replaceable (below ignored), maids vault-place from the material stock on claim instead of pathing or scaffolding
- 判断某种方块是否已经放够时，用开工时记下的蓝图需求数减去已建造数，不再在每次刷新队列时把整张蓝图重数一遍，避免大工程把服务器 tick 拖死
  - Whether a block type is fully placed is blueprint demand counted at start minus blocks already built, instead of rescanning the whole schematic on every queue refresh, so a large project no longer stalls the server tick
- 大型投影选址不再每帧重算方块模型：预览仍是半透明真实方块色、冲突格标红，并跟着镜头；模型只生成一次，移动落点或周围方块变化时才更新冲突红
  - Large schematic site-pick no longer rebuilds block models every frame. The preview stays translucent real block colors with per-cell conflict red and follows the camera; the mesh is baked once, and conflict red updates when the anchor or nearby blocks change
- 手持施工终端的材料库挂在世界存档、物品只留钥匙：背包不再同步整座 2700 格；同一存档里旧手持/已放置终端首次加载会把原库迁过去。放下再挖起沿用同一把钥匙；创造放下会给手里留下的那件另开钥匙以免和地上那台抢库；创造中键复制已绑定钥匙的终端只带钥匙不带整库
  - Portable terminal vaults live in world save data with only a key on the item, so inventory sync no longer carries all 2700 slots. Legacy held or placed terminals in the same world migrate on first load. Place then break reuses the same key; creative place forks a new key on the leftover item; creative middle-click of a bound terminal copies the key, not the full vault
- 蓝图标成空气的格子不建造，开工后也不会整盒拆掉草方块或石头。地表只在「覆盖地表」或「忽略重叠」开启、且挡住女仆寻路、站位或身体时拆掉入库；该格已经是蓝图要的方块则留下
 - Schematic air cells are not built, and grass or stone on them is not bulk-cleared after start. Surface is removed into the vault only when Cover Terrain or Ignore Overlaps is on and the block blocks the maid's path, stand, or body; a cell that already matches the schematic stays
- 缺料自动合成遇到配方标签时，只尝试材料库里已有、或当前库能一步喂饱的那种原料（优先原版），不再把整合包里其余替代物逐个展开；单次求解步数超限则这次视为合不成，直到库内容变化再试，避免开启自动合成后一次求解拖死服务器
 - Auto-craft on a recipe tag only tries ingredients already in the vault or one craft step from current stock (vanilla ids first) instead of expanding every modpack alternative; a solve that exceeds the step cap counts as uncraftable until the vault changes, so one solve cannot stall the server
- 工程页「缺失材料替换」：对当前游戏没有的蓝图方块，可指定替代物并计入材料库，女仆用替代物建造；点某一行「蓝图显示」只标出该种缺失方块的格子，其它材料不一起出现；须已确认选址，且与选址预览互斥（进入选址恢复完整蓝图和选址提示）；仅未开工/暂停时可改
 - Hub “Replace missing”: map registry-missing schematic blocks to substitutes that count in the vault and are built by maids; a row’s “Show” highlights only that missing block type after the site is confirmed, and does not replace the site-pick ghost (entering site pick restores the full schematic and its prompts); editable only when not actively building
- 每次点「开工」以及登录自动恢复在建工程时，按世界实况扫一遍蓝图格：缺块（非忽略）重新进待建，由女仆照常领单耗料补放，并从最低缺层继续施工。**同一种方块即视为已放对**（朝向/形状/含水等属性差异不算缺），不会拆掉再放；领单前再看一眼世界，清障也不铲同种蓝图格
 - Each Hub Start and login restore of a BUILDING project rescans the schematic against the world: missing non-ignored cells return to the pending queue for normal maid placement from the lowest incomplete layer. **The same block type already counts as placed** (facing/shape/waterlogged differences are not a miss), so maids do not break-and-replace those cells; claim rechecks the world, and cover-clear will not dig same-type schematic blocks
- 采购拆原料时：多配方先试原版；原料标签里只要有商城能买的就买原版那个（没有原版才买该标签里能买的）；拆不下去时也先试原版 id，避免整合包排在前面的替代配方把搜索步数用尽后箱子/骨块等拆不出来。库里已有的仍先合成再买缺口。单行搜索超过上限则该行视为无货
 - Ingredient expansion tries vanilla recipes first; if a tag has any mall item it buys the vanilla one (otherwise the first purchasable id); when it must recurse it also tries vanilla ids first so earlier modpack alternatives cannot spend the search budget and leave chests/bone blocks unexpanded. Vault stock is still crafted before buying the gap. A line that exceeds the search cap is treated as out of stock
- 采购清单用材料库计数时，可按单原料配方最多 3 跳生成虚拟存量（如骨头→骨粉→骨块），且**只朝本单缺料目标搓**（避免骨粉被搓成白染料等无关物后待购不减）；**本身已是本单缺料的物品不会被虚拟扣掉**，买进库的该物品会减少对应待购。只影响附属待购统计、不写入真实材料库；拆原料用真实库存优先再记购买
 - Purchase planning can augment vault counts with up to 3 hops of single-ingredient crafts toward current shortages only (e.g. bones → bone meal → bone block, without burning meal into unrelated dyes). Items that are themselves shortages are not spent as virtual ingredients, so buying them reduces that line. Companion buy lists only—no real vault writes; ingredient expansion uses real on-hand stock first then buys
- 缺料自动合成 / 附属采购拆原料支持**熔炉与高炉**虚拟烧炼（不计燃料），平滑石英等可拆到石英块再采购
 - Auto-craft / companion ingredient expansion virtually applies furnace and blast-furnace recipes (no fuel), so smooth quartz lines can resolve down to quartz blocks for purchase
- 缺料自动合成 / 附属采购拆原料的配方索引补上锯子、切木机等单输入切割类（与切石机同类），木台阶等不再因只有锯子配方而拆不出原料
 - Auto-craft / companion ingredient expansion now indexes single-input cutter recipes (sawmill, woodcutter, etc. alongside the stonecutter), so wood slabs can resolve when only those recipes exist
- 对外提供材料缺料快照 / 材料库写入 API，并支持附属模组在终端材料页注册按钮（供「施工队：多多采购」等联动）
 - Exposes shortage snapshot / vault deposit APIs and lets companion mods register Hub materials-page buttons (for Construction DuoDuo Supply and similar bridges)
- 材料库拒收带内含物的容器（如有物品的潜影盒、收纳袋）；空容器仍可放入，避免入库后取出变空
  - The material vault rejects containers that hold nested items (e.g. filled shulker boxes or bundles); empty containers are still allowed so contents are not wiped on deposit
- 蓝图待建为泥土或草方块时：世界已是其中任一则视为已满足、不挖不换；材料检测与领单也把泥土/草方块互相认作可用料（不含粗泥土等其它土壤）
  - When the schematic cell is dirt or grass block, either already in the world counts as done (no dig/replace); vault checks and claim also accept dirt and grass block interchangeably (not coarse/rooted dirt)
- 女仆领单时好做的格先做：就近候选里，附近有实地落脚点、下方有支撑、贴着已有方块的格优先；悬空、四面无依托的边缘格排到后面，不再一上来就往工地边缘高处跑。一个工位都没有的格算作拥挤，不再当成「有空工位」优先领
  - Maids claim easy cells first: among nearby candidates, cells with solid footing nearby, support below and attached neighbours go first, while floating edge cells with nothing around wait, so maids no longer run straight to high edges of the site. A cell with no work stand at all counts as crowded instead of being preferred as having a free stand
- 无可用工位且目标格被其它可破坏方块占用时：立刻拆掉该格（战利品进库）并库放置待建方块，不依赖「覆盖地表 / 忽略重叠」；基岩等不可破坏仍不拆，库无料则无法放置
  - With no work stand and a wrong destroyable block on the target cell: immediately dig that cell into the vault and vault-place the schematic block, independent of Cover Terrain / Ignore Overlaps; unbreakable blocks stay; missing materials still block placement
- 工地内若手里有认领却没有工位，不再每约 5 秒 stuck 传送旁移 1 格（日志里同 X 两格来回）；须有工位才允许卡住救援；**无工位时立刻库隔空放置**；**有工位时卡住先传送到工位**（隔空不会抢在传送前面）；认领满约 30 秒也必须松手
  - On-site maids holding a claim with no work stand no longer stuck-teleport one block sideways every ~5s; stuck rescue requires a work stand; **with no stand they vault-place immediately**; **with a stand, stuck recovery teleports to it before any vault-place**; claims still release at the ~30s timeout
- 去工位改为真走路：近距不再瞬移贴格；导航结束不会每 tick 重寻路（近处精确路径、冷却后再试），避免进一格退一格和平移无朝向
 - Walking to a stand uses real pathing: no adjacent teleport snap; finished nav no longer repaths every tick (exact path when close, cooldown before retry), so maids stop oscillating and sliding without facing
- 原版寻路预检、脚手架全量重规划、全量搜路不再设每女仆 / 每拍额度；找可走工位时一次最多试约 8 个站位的可达性，避免候选格过多时连跑寻路拖死 tick
  - Vanilla path pre-check, full scaffold replan, and heavy path search no longer use per-maid / per-tick quotas; reachable-stand search still caps about 8 path probes per attempt so huge candidate sets cannot stall a tick
- 层上「有无可放」只按库存索引、按方块种类去重判断，不再对上千格逐格 hasMaterial（避免连带自动合成把一拍拖到数秒、客户端把位置跳变插成平移）；自动合成失败按当前仓库内容记住，库没变就不再每 tick 重解配方；每拍最多求解约 2 次，避免第一种无配方材料单独卡死整 tick
  - “Has placeable on layer” uses the stock index and unique block ids instead of hasMaterial on every pending cell (which was triggering auto-craft and stalling ticks for seconds, so the client interpolated jumps as sliding); failed auto-craft ids stay memoized until vault contents change; at most ~2 craft solves per tick so one uncraftable id cannot stall the whole tick
- 领单改为以女仆（或上次放置点）为中心向外「雷达」扫：每轮最多查约 48 格材料，跨 tick 记住游标续扫，避免大层一次扫上千格拖死服务端；整圈仍无料才短暂停扫
  - Claim scans now radar outward from the maid (or last placed block): ≤~48 material checks per pass with a cross-tick cursor, so large layers no longer material-scan thousands of cells in one go; starve only after a full pass finds no stock
- 相对待建第一层（起始层滤后）施工第 1、2 层时不规划临时脚手架，从第 3 层起恢复正常搭架
  - Scaffold planning is disabled while building relative floors 1–2 after the start-layer trim; from floor 3 upward scaffolding works as usual
- 够不着时：**有工位先走路/卡住传送到工位**，隔空不会抢先；**完全无工位时立刻库隔空**；脚手架规划失败 escalate 时若仍有工位则继续走/传送，不再 defer 松手
  - When out of reach **with a stand, walk or stuck-teleport to it first** (vault never skips ahead); **with no stand, vault-place immediately**; scaffold plan-fail escalate with a stand keeps walking/teleporting (no defer-release)
- 领单存活检测真正按预算截断（最近约 96 格内最多约 48 次 canSurvive），并对「层上是否有可放任务」做短缓存，避免大层多女仆每 tick 扫上千格拖死服务端；缺料等待时停在原地（不跟随、不工地救援、主人走远也不传送过来），大约每 10 秒重扫一次材料库，界面里新放入的泥土、草方块等会被认到并继续施工
  - Claim survival checks now actually apply the budget (nearest ~96 stocked cells, ≤~48 canSurvive), and “has placeable on layer” is short-cached so large layers with multiple maids no longer full-scan thousands of cells every tick; on material wait maids stay put (no follow, site rescue, or owner-distance teleport) and rescan the vault about every 10 seconds, so dirt, grass blocks, and other items placed in the terminal GUI are noticed and building resumes
- 选址页可设「起始层」：相对蓝图底跳过更低层（不预览、不算料、不施工）；开工后锁定，便于处理带多余地下垫层的投影
  - Site page Start Layer skips lower schematic Y cells (no preview/materials/build); locked after start, for schematics with extra buried foundation layers
- 领单存活检测每轮最多约 48 格，并先按距离截断再做工位分散；避免大层有料时对整层跑 canSurvive 拖死服务端
  - Claim survival checks are capped (~48 per pass) after a distance-based truncate before stand-spread, so stocked large layers no longer run canSurvive on every pending cell and stall the server
- 女仆清障/放置前清掉的方块会正确进入终端材料库（自动合成等包装层不再导致整堆掉地；库满才在挖点旁掉落）
  - Blocks cleared by construction maids (cover/ignore clear and pre-place mismatch clear) deposit into the terminal vault again through material-source wrappers; leftovers only drop beside the dig site when the vault is full
- 领单查料改为增量库存索引（按 item 加减计数，缺料短暂停扫），避免大蓝图多女仆每 tick 全表扫材料库拖死服务端
  - Claim material checks use an incremental stock index (per-item counts, brief starve when a layer has no stock) so large blueprints with multiple maids no longer full-scan the vault every tick and stall the server
- 施工终端材料库 Shift 从背包转入时写入整库 2700 格，不再只填当前可见页（避免一页满却后面还有空页时像整库已满）
  - Shift-clicking from the player inventory into the construction terminal vault now deposits across all 2700 slots, not only the visible page
- 施工工程可开关「缺料自动合成」（默认关）：库无成品但有原料时，按工作台/切石机配方虚拟递归合成入库（允许溢出），再供女仆使用；失败则仍按原缺料气泡规则；同库状态下对已判定无法合成的材料做记忆，避免领单扫描时反复求解拖慢服务端；库位不足时只要有产出入库即算成功，且开启自动合成时不再把失败材料永久拉黑；工作台成型配方会把多格同种材料合并计数（如原木/木→木板→告示牌）

  - Construction hot paths emit `[TMC-Perf]` timings (claim / auto-craft / maid phase / full tick); WARN when a step ≥25ms or a tick ≥50ms so the next stall can be pinned from logs
