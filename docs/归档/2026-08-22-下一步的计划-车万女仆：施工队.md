> **For agentic workers:** 按阶段验收推进；每完成一阶段将对应 `- [ ]` 改为 `- [x]`。全部完成后按工作区规则归档到 `docs/归档/`。  
> **脚手架：** 本计划**不做**；待下列阶段全部跑通后再开新讨论/新计划。

**Goal:** 自研极简 `.litematic` 预览 + 施工终端 + 多女仆按蓝图协同建造（1.20.1 Forge，硬依赖车万女仆），不依赖有缺陷的 Forge 投影移植。

**Architecture:** 蓝图解析（内存）→ 客户端幽灵预览（不写存档）→ 施工终端（物品⇄方块，材料库）→ 服务端 `BuildJob` 任务队列 → 女仆抢单执行（触及优先 / 局部队列 / 站位复用；不可达则隔空直接放置）。预留 `Blueprint` / `BuildJob` / `BuildTask` 接口。

**Tech Stack:** Minecraft **1.20.1** / Forge **47.x**（与《好好吃饭》《一起挖矿》同线）；Java 17；官方 mappings；硬依赖 Touhou Little Maid。

## 1. 产品目标（本计划范围）

玩家能：

1. 使用**施工终端**（物品可放置为方块，撬起变回物品，材料随身）  
2. 三页 GUI：投影/工程管理 → 工程页（选址/预览/冲突）→ 施工页（女仆/进度/材料）  
3. 加载 `.litematic`，选点预览落点（幽灵方块 + 冲突标红）  
4. 材料存在终端内；女仆**每成功放 1 块扣 1 份**  
5. 多女仆加入同一工程，**抢单队列**协同  
6. 尽量**完整还原**蓝图内容（方块状态 + 方块实体 + 实体）；缺失 id 跳过并报告  

**明确不做（本计划）：**

- 脚手架垫高与回收（其它功能跑通后另开计划）  
- 依赖任何 Litematica Forge 移植  
- 自研蓝图格式（第一期只读 `.litematic`）  
- 复杂手动分区派工

## 2. 功能规格

### 2.1 施工终端

| 项 | 规格 |
|----|------|
| 形态 | 物品 ⇄ 方块；材料与工程状态随终端持久化 |
| 防毁 | **不可**被岩浆、仙人掌等环境破坏；玩家可正常拆除/撬起 |
| 材料 | 玩家在终端 GUI 存入；建造时按块扣除，**禁止开工时一次性扣光** |

### 2.2 GUI（三页）

**页面 1 — 投影/工程管理**

- 左侧列表：已加载投影、进行中工程（类似侧栏文件夹）  
- 选择 `.litematic` 文件；管理已加载项  
- 点击某工程 → 进入该工程的页面 2  

**页面 2 — 工程页**

- 所需材料清单  
- 选择落点（进入选点模式）  
- 预览模式开关相关  
- 冲突 / 缺失报告  
- 贴地向上（默认）与「覆盖地表」开关  
- 选址完成且无冲突禁开工条件满足后 → 可进页面 3  

**页面 3 — 施工页**

- 施工女仆列表与选择（支持多选）  
- 施工进度  
- 已消耗材料、当前缺失材料  
- 开工 / 暂停  

### 2.3 落点与冲突

| 项 | 规格 |
|----|------|
| 选点 | 退出 GUI → 准星点方块定锚点 → 世界幽灵预览 → 确认后回终端 |
| 默认可放 | 空气 + `canBeReplaced()` |
| 默认落点 | **贴地向上**（点在草方块顶面，建筑往上盖，不挖地表） |
| 可选 | 「覆盖地表」（草方块 / 泥土 / 沙子等） |
| 冲突 | 预览标红；存在冲突则**禁止开工** |
| 预览 | 仅客户端；**不写世界 / 不腐档** |

### 2.4 蓝图

| 项 | 规格 |
|----|------|
| 格式 | `.litematic` |
| 内容 | 方块状态 + 方块实体 NBT + 实体；能解析的不丢 |
| 缺失 | 当前世界不存在的方块/实体：**跳过**并写入报告（不整份拒绝） |

### 2.5 女仆放置（无脚手架版）

**选点与移动策略（方案 A）：**

1. **触及优先：** 放成功后先不走，清空当前站位下「触及 + 视线内」全部待放  
2. **局部优先队列：** `localQueue`，曼哈顿距离 ≤ R（默认 5），按距离排序；空了才全局「离我最近」  
3. **站位复用：** 脚点仍可站且下一目标仍可及则不动；脚点被挡则重新 `findWorkPosition`  
4. **失效：** 已放置、被挡、Job 暂停等 → 清/重建局部队列  

**像度：** 偏玩家（走近可达站位、面向目标、接近原版放置规则）；非完整交互包模拟。

**寻路超时：** 参考《一起挖矿》——约 **40 tick（2 秒）** 同方块位置未移动则取消当前路径，记暂时不可达并换目标（实现可抽成同类策略类）。

**不可达（本计划，无脚手架）：**

1. 普通放置（含寻路/站位）失败且超时/不可达  
2. → 标记该待放为不可达  
3. → **直接放置（方案 B）：** 服务端对目标格 `setBlock` / 恢复方块实体 / 生成实体，**无视触及与视线**；成功仍扣终端对应材料  

> 日后加脚手架时：插入为第 2 步「尝试脚手架后再判不可达」；不可达后的直接放置规则保持 B。

**多女仆：** 同一 `BuildJob` 共用待办队列；谁空闲谁领下一个可执行任务。

**扣料：** 仅在放置成功后扣 1；失败不扣。缺料则暂停并在页面 3 提示，补料后续建。

### 2.6 安全原则

- 预览与解析不修改世界方块  
- 唯有 `BuildJob` 执行路径改世界  
- 终端与 Job 状态可序列化，卡退可恢复，避免投影过程腐档
