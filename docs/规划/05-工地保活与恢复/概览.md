# 工地保活与恢复

## 1. 定位与目标

保证施工工程在**存档重进、暂停再开、女仆 AI 绑定丢失**等情况下仍能回到正确状态，而不是误把已完工工程拉回、或让女仆长期卡在「已暂停 / 已束缚 / 材料计数错乱」的中间态。

**成功标准：** 玩家重登后，附近女仆能自动续建未完工工程；点完工后状态与世界一致且束缚解除；材料页与已放置进度、已消耗库存与终端持久化一致。

## 2. 玩家体验 / 玩法流程

1. 放置终端、确认蓝图、开工 → 女仆施工（可能暂停、重登、换设备）。
2. 重进存档 → **无需手动点恢复**，附近女仆应自行回到工地继续；终端材料页显示的数量应已扣掉已放置部分。
3. 工程做完（自动完工或终端强制完工）→ 状态变为已完成，女仆解除工地束缚，工作模式回空闲，不再被拉回旧任务。

## 3. 内容边界

### 做

- 重进存档时自动恢复**在建**工程（非全维度扫女仆，仅玩家附近）。
- 暂停后再开工、或内存里 Job 绑定丢失时，由 AI 侧恢复施工意图；恢复时清除「暂停 / 跟随记忆」以免女仆仍像闲置跟随。
- 完工同步 **DONE**，解除女仆束缚并将工作模式切回**空闲**；已完工或世界已按蓝图放满时**不**误恢复为在建。
- 材料页「还需」合并已保存的放置计数；已消耗材料从终端持久化还原；还需为 0 时不再向玩家索要；已计满仍留在队列里的待铺格应丢弃。
- 施工终端免疫环境破坏（爆炸、流体等常规破坏）。
- 施工进行中与工地区块相关的保活思路（细节见主题文，未完全核实的标「待核实」）。

### 不做

- 登录时不遍历全维度、全女仆做恢复（性能与职责边界）。
- 把已完工或世界已匹配的工程强行拉回在建。
- 在本模块内定义清障、脚手架、寻路细则（见 06、04、03 模块）。

1. **核实**工地区块保活：加载半径、与蓝图 AABB 关系、是否与原版 chunk ticket 叠加——写清掌舵规则或标长期「待核实」。
