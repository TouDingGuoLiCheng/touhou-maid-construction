# 采购虚拟单原料库存

## 要解决什么

附属采购清单拆原料时，若材料库里已有「单种原料即可合成」的上游物（如骨头→骨粉），不应再把整段需求记成待购；虚拟计入可合成量，**不**写入真实材料库格子。

## 期望行为

- **仅采购清单 / 待购统计**使用虚拟存量；缺料面板、自动合成、真实扣料仍只认真实库。
- 仅「合并后恰好一种原料」的配方参与虚拟（允许 count>1，如 9 骨粉→1 骨块）；多原料配方不扩。
- 在真实计数副本上最多 **3 跳**：每跳扣原料、加产物；真实库不变。
- **按当前工程缺料目标过滤**：只虚拟搓「能通向本单缺料 purchase 身份」的产物（含中间物闭包），避免骨粉被无关单原料配方（如白染料）抢先耗尽导致待购不减。**本单缺料自己不拿去当原料**：库里已有的木板不会被虚拟搓成楼梯后再把木板算成没有。
- 拆原料规划：用**真实库**计数先合成再记购买（不依赖已被虚拟改写的副本）。同一成品有多条配方或原料是大标签时，**先试原版**，避免整合包排在前面的替代物把单行搜索步数用尽后连箱子都拆不出原料。
- 采购 UI **不**提示「虚拟」——只表现为待购数量变少或行消失。

## 当前完成度与已知缺口

- **已有：** 施工队按需虚拟存量 + API；采购拆原料 planner 先搓后买；多多采购传入本单目标 id。
- **缺口：** 多原料虚拟；缺料/自动合成认虚拟（刻意不做）。
