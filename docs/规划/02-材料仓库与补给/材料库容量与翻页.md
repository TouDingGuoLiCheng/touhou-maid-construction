# 材料库容量与翻页

## 要解决什么

给大型蓝图准备**足够深的储物**，同时让翻页操作在 GUI 里**可预期**（整页切换，而不是一格一格滑）。

## 期望行为

**容量**

- 终端材料库共 **2700 格**。  
- 分页：**100 页**，每页 **3 行**（行数 × 每行槽位数 = 单页容量；总页数凑满 2700）。

**翻页**

- 在材料库界面用**滚轮**切换时，按**整页**跳转（不是单槽滚动）。  
- 页码或等价指示让玩家知道当前在第几页。  
- **搜索：** 输入框按物品**显示名或 registry id**（忽略大小写、子串）过滤；只显示匹配的非空格，翻页只在结果里走。清空输入恢复 100 页。**过滤不重排、不压紧真实 2700 格。** 搜索框聚焦时 **Esc 关闭界面**；输入时 E 不关库。  
- **翻到哪一页，该页格子里的物品应立刻可见**（手持终端库不进背包同步时也一样），不需要点空格才刷出来。  
- 存入的物品持久化：放置终端写在方块上；**手持终端写在世界存档**（物品只留钥匙），重进存档仍在。

**与清单关系**

- 材料库是**通用储物**；「还需要多少」以工程材料页统计为准，不要求一格一类（玩家可混放，扣料按物品类型匹配）。

## 触发、条件与边界

- **触发：** 选址与材料页或 Hub 内打开材料库 GUI。  
- **边界：** 2700 为硬上限，超出需玩家另建终端或腾挪（无自动合并多终端库的计划）。  
- **边界：** 翻页仅影响**查看/点选格**；界面每次只同步**当前页窗口**，整库仍在服务端/世界存档。  
- **边界：** Shift 从背包转入材料库时写入**整库 2700 格**（不会因当前页满就判整库满）。  
- **边界：** **有内含物的容器**（如装了东西的潜影盒、收纳袋等）**不可放入**材料库；空容器可以。避免入库路径丢掉 NBT 后「拿出来变空」。  
- **边界：** 搜索只改窗口映射；写回只打已映射槽；无结果时空窗口不得清空真实库。Shift 存入仍写整库。  
- **边界：** 搜索聚焦时 Esc 必须能关 GUI，不得被输入框吞掉。  
- **不做：** 自动整理、按蓝图一键分槽、拼音模糊搜。

## 当前完成度与已知缺口

- **已有：** 100 页、每页 3 行、共 2700 格；滚轮整页翻页；翻页后当前页立即显示（含手持钥匙库）；拒收有内含物的容器；显示名/id 搜索过滤（不重排真实库）。  
- **待核实：** 末页未满时的 UI 提示是否清晰。  
- **缺口：** 无已知容量/翻页功能缺口。
